## 简介

[![网页浏览器演示](https://img.shields.io/badge/demo-try%20in%20browser-blue?style=for-the-badge&logo=firefoxbrowser)](https://copy.sh/v86/?profile=copy/skiffos)

[SkiffOS] 是用于 [Buildroot] 操作系统交叉编译器的配置包系统。

 - **随处运行任意发行版**：将硬件支持与用户发行版环境解耦。
 - **可靠**：极简只读宿主系统，实现牢不可破的启动和 OTA 更新。
 - **可复现**：离线构建、固定软件包版本、纳入版本控制的定制配置。

配置包会合并在一起以配置系统，例如：

 - `SKIFF_CONFIG=intel/desktop,core/fedora` - 在 amd64 PC 上运行 Fedora 桌面
 - `SKIFF_CONFIG=pi/4,core/debian` - 在 Raspberry Pi 4 上运行 Debian 桌面。
 - `SKIFF_CONFIG=virt/qemu,custom/config` - 在 QEMU 虚拟机中运行自定义配置。

有一个[项目模板][project template]可用于版本控制的定制。

Linux 设备对内核、固件和其他硬件支持包有不同要求。SkiffOS 将这类支持与容器化环境解耦。容器可在具有相同 CPU 架构的设备之间移植，而普通操作系统镜像（板级支持包）则不能。

支持[任何兼容 Linux 的计算机][any Linux-compatible computer]，涵盖从 [RPi]、[Odroid]、[NVIDIA Jetson]，到 [桌面 PC][Desktop PCs]、笔记本电脑（即 [Apple MacBook]）、[手机][Phones]、[云虚拟机][Cloud VMs]，甚至 [Web 浏览器][Web Browsers]。

## 快速开始

[![支持服务器](https://img.shields.io/discord/803825858599059487.svg?label=Discord&logo=Discord&colorB=7289da&style=for-the-badge)](https://discord.gg/EKVkdVmvwT)

必须安装 [Buildroot 依赖项]作为前提条件，假设使用 apt：

```
sudo apt-get install -y \
  bash \
  bc \
  binutils \
  build-essential \
  bzip2 \
  cpio \
  diffutils \
  file \
  findutils \
  git \
  gzip \
  libarchive-tools \
  libncurses-dev \
  make \
  patch \
  perl \
  rsync \
  sed \
  tar \
  unzip \
  wget
```

[Buildroot 依赖项]: https://buildroot.org/downloads/manual/manual.html#requirement-mandatory

此示例使用 `pi/4` 用于 Raspberry Pi 4，参见[支持的系统]。

[支持的系统]: #supported-systems

在开发机器上[创建 SSH 密钥]。使用 `cp ~/.ssh/*.pub ./overrides/root_overlay/etc/skiff/authorized_keys` 将公钥添加到构建中。这是启用 SSH 访问所必需的。

[创建 SSH 密钥]: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent#generating-a-new-ssh-key

```sh
$ git submodule update             # 确保 buildroot 是最新的
$ make                             # 列出所有可用选项
$ export SKIFF_WORKSPACE=default   # 可选：同时支持多个 SKIFF_CONFIG
$ export SKIFF_CONFIG=pi/4,skiff/core
$ make configure                   # 配置系统
$ make compile                     # 构建系统
```

运行 `make configure` 后，你的 `SKIFF_CONFIG` 选择将被保存。构建可以中断，之后用 `make compile` 恢复。

`SKIFF_WORKSPACE` 默认为 `default`，用于同时编译多个 `SKIFF_CONFIG`。

Buildroot 还提供了许多其他实用命令，可以使用 `make br/help` 列出，一些示例：

```sh
$ make br/menuconfig # 浏览 Buildroot 配置菜单
$ make br/sdk        # 为目标构建可重定位 SDK
$ make br/graph-size # 绘制目标软件包大小图表
```

还有其他[应用包]可用，例如 `apps/crio`。

[应用包]: ./configs/apps

### 刷写 SD 卡

构建完成后，就可以将系统刷写到 SD 卡了。在大多数系统上，你需要切换到 `sudo bash`。

```sh
$ sudo bash             # 切换到 root
$ blkid                 # 查找你的 SD 卡设备文件
$ export PI_SD=/dev/sdz # 确保这是正确的！
$ make cmd/pi/common/format  # 告诉 skiff 格式化设备
$ make cmd/pi/common/install # 告诉 skiff 安装操作系统
```

设备只需格式化一次，之后，安装命令可用于更新 SkiffOS 镜像而不清除持久数据。持久分区在此步骤中不会被触及，因此你保存在那里的任何内容，包括所有 Docker 容器和系统配置，都不会被修改。

### 连接

使用 SSH 连接到 `root@my-ip-address` 以访问 SkiffOS 系统，连接到 `core@my-ip-address` 以访问“Core”系统容器。如果出现密码提示，请参阅上面关于 SSH 公钥的部分。

用户和容器之间的映射可以在 `/mnt/persist/skiff/core/config.yaml` 文件中编辑。

### OTA 升级

然后可以使用 rsync 脚本通过无线（OTA）升级系统：

```sh
$ ./scripts/push_image.bash root@my-ip-address
```

SkiffOS 升级（或降级）将在下次重启时生效。

### 在 MacOS 上编译

目前还不能直接在 MacOS 上构建，特别是由于 MacOS 文件系统不区分大小写。你可以使用 Lima 来构建操作系统：

[安装 Lima](https://github.com/lima-vm/lima?tab=readme-ov-file#getting-started)，然后：

```bash
limactl start --name=skiffos-build https://raw.githubusercontent.com/skiffos/SkiffOS/master/build/lima/lima.yaml
limactl shell skiffos-build
```

然后在 lima shell 中：

### 自定义容器配置

默认配置创建一个名为“core”的用户映射到容器中，但可以通过 `skiff-core.yaml` 配置文件进行调整：

```yaml
containers:
  core:
    image: skiffos/skiff-core-gentoo:latest
    [...]
users:
  core:
    container: core
    containerUser: core
    [...]
```

上面支持的发行版提供的[示例配置]是进一步自定义的良好起点。

[示例配置]: https://github.com/skiffos/SkiffOS/blob/2022.08.1/configs/skiff/core/buildroot_ext/package/skiff-core-defconfig/coreenv-defconfig.yaml#L11

要自定义正在运行的系统，编辑 `/mnt/persist/skiff/core/config.yaml` 并运行 `systemctl restart skiff-core` 以应用。更改容器配置后，你可能需要删除现有容器并重启 skiff-core 以重新创建它们。

要在配置包中覆盖默认的 skiff-core 配置，你可以将 `.yaml` 文件放在 `root_overlay` 中的以下位置：`root_overlay/opt/skiff/coreenv/defconfig.yaml`。这允许你作为构建的一部分自定义容器配置。

配置格式和 skiff-core 源代码位于[skiff-core 仓库]。

[skiff-core 仓库]: https://github.com/skiffos/skiff-core/blob/master/config/core_config.go

## 配置包

SkiffOS 支持模块化配置包：内核和 buildroot 配置、根文件系统覆盖、补丁、钩子和其他资源。

层命名为 `namespace/name`。例如，Raspberry Pi 4 配置为 `pi/4`，Docker 为 `apps/docker`。

```
├── cflags:         文件中的编译器标志
├── buildroot:      buildroot 配置片段
├── buildroot_ext:  buildroot 扩展（额外软件包）
├── buildroot_patches: 额外的 Buildroot 全局补丁
│   ├── <packagename>: Buildroot <packagename> 的补丁文件
│   └── <packagename>/<version>: 软件包版本的补丁
├── busybox:        busybox 配置片段
├── extensions:     添加到构建系统的额外命令
│   └── Makefile
├── hooks:          挂接构建前/后步骤的脚本
│   ├── post.sh
│   └── pre.sh
├── kernel:         内核配置片段
├── kernel_patches: 内核 .patch 文件
├── root_overlay:   根覆盖文件
├── metadata:       元数据文件
│   ├── commands
│   ├── dependencies
│   ├── description
│   └── unlisted
├── resources:     配置包使用的文件
├── scripts:       扩展使用的任何脚本
├── uboot:         u-boot 配置片段
├── uboot_patches: u-boot .patch 文件
└── users:         额外的 buildroot 用户配置文件
```

所有文件都是可选的。

### 自定义用户

要添加自定义用户，请在“users”目录中添加文件，使用 [makeuser 语法]。

[makeuser 语法]: https://buildroot.org/downloads/manual/manual.html#makeuser-syntax

### 树外配置包

你可以设置以下环境变量来控制此过程：

 - `SKIFF_CONFIG_PATH_ODROID_XU`：设置 ODROID_XU 配置包的路径。你可以设置此项以添加新包或覆盖旧包。
 - `SKIFF_EXTRA_CONFIGS_PATH`：以冒号 `:` 分隔的路径列表，用于查找配置包。
 - `SKIFF_CONFIG`：要使用的 skiff 配置名称，或以逗号分隔的叠加列表，后面的选项优先

这些包将在 SkiffOS 系统中可用。

### 覆盖

在开发过程中，无需实际创建新的配置层即可调整配置通常很有用。这可以通过 [overrides](./overrides) 层轻松完成。

overrides 目录被视为附加配置层。配置层的布局如上所述。Overrides 被 Git 忽略，是快速轻松修改配置的方法。

要应用更改并重新打包构建，请再次运行 "make configure compile"。

## 工作区

使用工作区同时编译多个 `SKIFF_CONFIG` 组合。

`SKIFF_WORKSPACE` 环境变量控制选择哪个工作区。

`workspaces/$SKIFF_WORKSPACE` 目录包含 Buildroot 构建目录。

`overrides/workspaces/$SKIFF_WORKSPACE/` 中的配置文件将使用配置包结构覆盖该工作区的设置。

## 虚拟化

virt/ 包设计用于在各种虚拟化环境中运行 Skiff。

### Qemu

以下是在 Qemu 中运行 Skiff 的最小工作示例：

```sh
$ SKIFF_CONFIG=virt/qemu,util/rootlogin make configure compile
$ make cmd/virt/qemu/run
```

这里使用 `util/rootlogin` 包是为了在运行 "cmd/virt/qemu/run" 时显示的 qemu 调试控制台上启用 "root" 登录。

[Devices workflow](https://github.com/skiffos/SkiffOS/actions/workflows/devices.yml) 在成功的 `master`、`next` 和 `stable` 构建中，为 `virt/qemu` 目标发布相同的 Buildroot 镜像目录，名为 `images-virt-qemu.tar.gz`。该工件包含 `cmd/virt/qemu/run` 使用的内核、initramfs 和 rootfs 文件；它不是独立的 ISO 或磁盘镜像。

Qemu 可以模拟其他架构，例如 riscv64：

```
export SKIFF_WORKSPACE=qemu
export SKIFF_CONFIG=virt/qemu,core/gentoo,util/rootlogin
mkdir -p ./overrides/workspaces/qemu/buildroot
echo "BR2_riscv=y" > ./overrides/workspaces/qemu/buildroot/arch
make compile
```

大多数 Buildroot 支持的架构都可以选择和模拟。

运行虚拟机的参数也可以调整：

```
export ROOTFS_MAX_SIZE=120G
export QEMU_MEMORY=8G
export QEMU_CPUS=8
make cmd/virt/qemu/run
```

### Docker

以下是在 Docker 中运行 SkiffOS 的最小工作示例：

```sh
$ SKIFF_CONFIG=virt/docker,skiff/core make configure compile
$ make cmd/virt/docker/buildimage
$ make cmd/virt/docker/run

# 在容器内
$ su - core
```

构建命令编译镜像，运行命令执行它。

你可以使用以下命令在容器内执行 shell：

```sh
$ make cmd/virt/docker/exec
# 或者
$ docker exec -it skiff sh
```

或者运行 Docker Hub 上最新的演示版本：

```
docker run -t -d --name=skiff \
  --privileged \
  --cap-add=NET_ADMIN \
  --security-opt seccomp=unconfined \
  --stop-signal=SIGRTMIN+3 \
  -v /sys/fs/cgroup:/sys/fs/cgroup:ro \
  -v $(pwd)/skiff-persist:/mnt/persist \
  skiffos/skiffos:latest
```

## 配置

SkiffOS 还可以使用“persist”分区中的文件进行配置。

### 主机名

通过将所需的主机名放入 persist 分区上的 `skiff/hostname` 文件来设置主机名。你也可以在某个配置包中将所需主机名写入 `/etc/hostname`。

### NetworkManager

你可以在设备上使用 `nmcli` 管理 `NetworkManager`，通过 `nmcli device wifi connect` 或类似命令写入的任何连接定义都将自动写入 persist 分区并在未来启动时持久化。

要连接到 WiFi：`nmcli device wifi connect myssid password mypassword.`

这些连接的配置文件格式[在此处记录](http://manpages.ubuntu.com/manpages/wily/man5/nm-settings-keyfile.5.html)，并附有示例。

名为 `mywifi`、密码为 `mypassword` 的 WiFi 网络示例：

```
[connection]
id=mywifi
uuid=12f6c21d-f077-4b95-a4cb-bf41555d87a5
type=wifi

[wifi]
mode=infrastructure
ssid=mywifi

[wifi-security]
key-mgmt=wpa-psk
psk=mypassword

[ipv4]
method=auto

[ipv6]
addr-gen-mode=stable-privacy
method=auto
```

网络配置文件是纯文本文件，位于以下任一位置：

 - 构建镜像内的 `/etc/NetworkManager/system-connections/`
 - persist 分区上的 `/mnt/persist/skiff/connections/`。

要将上述示例添加到你的构建中：

 - `gedit ./overrides/root_overlay/etc/NetworkManager/system-connections/mywifi`
 - 粘贴上述纯文本并保存
 - 运行 "make compile" 以使用更改更新镜像。

### SSH 密钥

系统将在启动时为用户生成 authorized_keys 文件。

它从以下位置获取 SSH 公钥文件（`*.pub`）：

 - 镜像内的 `/etc/skiff/authorized_keys`
 - persist 分区内的 `skiff/keys`
 
你的 SSH 公钥通常位于 `~/.ssh/id_ed25519.pub`。

### 将磁盘挂载到容器

要将 Linux 磁盘（例如 `ext4` 分区）挂载到 Docker 容器内的路径，你可以使用 Docker Volumes 功能：

```sh
# 为存储驱动器创建卷
docker volume create --driver=local --opt device=/dev/disk/by-label/storage storage

# 运行临时容器查看内容
docker run --rm -it -v storage:/storage --workdir /storage alpine:edge sh
```

可以通过在 `/mnt/persist/skiff/core/config.yaml` 中的 mounts 列表添加以下内容，将卷挂载到 Skiff Core 容器：

```yaml
containers:
  core:
    image: skiffos/skiff-core-gentoo:latest
    mounts:
      - storage:/mnt/storage
```

添加挂载后，删除并重新创建容器：

```sh
docker rm -f core
systemctl restart skiff-core
```
